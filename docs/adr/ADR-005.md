# ADR-005: El estado «Sin confirmar» se calcula, no se almacena

**Estado:** Aceptada (diseño objetivo P2 v1.1)  
**Fecha:** 2026-11-28

## Contexto
RF-10 y RF-11: tres etiquetas visibles; Sin confirmar a T+30 min.

## Decisión
intake_logs solo guarda pending/taken; Sin confirmar = pending y ahora > scheduled_for + 30 min.

## Alternativas consideradas
Guardar un tercer estado mediante tarea programada.

## Fundamento
Evita tareas en segundo plano y estados inconsistentes.

## Consecuencias
El cálculo debe usar America/Mexico_City en cliente y servidor.
